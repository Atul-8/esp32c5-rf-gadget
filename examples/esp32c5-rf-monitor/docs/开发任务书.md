# 基于 ESP32-C5 射频监测的五功能分治开发任务书

> **这份文档是发给执行 AI 的施工令。** 核心方法论：[ai-coordination](https://github.com/Atul-8/ai-coordination) 七层分治框架（本地已安装）。
> 你（执行 AI）每一次会话开工前必须重读本文档 + `todo.md`，因为你是"低智"工人，不重读就会跑偏。

## 〇、写给执行 AI 的四条生存法则

1. **你只做当前阶段的任务。** `todo.md` 里标记 `[DOING]` 的那一项，做完就停，输出验收包，等人。绝不提前做下一项。
2. **STOP 就是 STOP。** 每个功能完成后的 STOP 门禁是硬性的：没有人类回复"确认完成"四个字之前，不许创建下一个分支，不许写下一行功能代码。
3. **不改别人的地基。** 功能分支上**禁止修改 `core/` 目录任何文件**。如果发现 core 接口不够用，停下来，在 `todo.md` 写明需求，等人裁决。
4. **todo.md 是唯一事实源。** 每完成一小步就更新 `todo.md` 状态。你的记忆不可靠，文件才可靠。

## 一、核心哲学：ai-coordination 分治思维（本项目的宪法）

本地已安装 [ai-coordination](https://github.com/Atul-8/ai-coordination) 插件。它的核心思想是**七层分治 + 流水线治理**：

```
coordination（协调）→ presentation（表示）→ interface（接口）→ core（核心）
                    → shared（共享）+ testing（测试）+ docs（文档）
```

对应到本项目：

| ai-coordination 层 | 本项目落点 | 规则 |
|---|---|---|
| coordination | `todo.md` + `.ai/` + 本文档 | 任务的登记、状态、验收全部走这里，不写邮件不写口头 |
| interface | `core/registry.py` 模块契约 | 所有功能模块只通过契约接线，这是合并时不冲突的保证 |
| core | `core/`（串口、快照、调度器、存储） | 只有阶段 0 能创建，功能分支只调用不修改 |
| presentation | `output/`（表格/瀑布图/报告/告警） | 每个功能自带自己的输出实现 |
| shared | 统一数据 schema（见下文） | 任何模块不得自造数据格式 |
| testing | `tests/` 每功能必带 mock 测试 | 硬件不在手边也要能全量自测 |
| docs | `docs/` 每阶段产出一份说明 | STOP 门禁的验收材料 |

框架的 G0–G4 铁律照常生效：**路由**（开工先看 todo.md 定位任务）、**自动化**（能用测试验证的不靠嘴说）、**自查**（提交前跑全量测试）、**错误提炼**（报错走 `/error` 五步，提炼后记入 todo.md，不许原地瞎试超过两次）、**离场**（阶段做完把状态写干净再走）。

**命令对照**（按你本地实际安装的形态取用）：

| 时机 | 命令 | 作用 |
|---|---|---|
| 项目初始化（仅一次） | `/coord-init` | 生成 AGENTS.md / todo.md / .ai/ / docs/plans/ |
| 每个阶段开工前 | `/plan` | 只读探索→计划落盘 `docs/plans/`→登记 todo |
| 阶段执行 | `/go sX` | 按序执行本阶段任务项 |
| 遇到报错 | `/error` | 五步错误提炼，禁止绕过 |
| 阶段完成（STOP 前） | `/meta` + `/status` | 沉淀经验 + 产出验收状态报告 |

## 二、Git 分支模型

```
main ──●──────────────────────────────────●── merge all ──→ v1.0.0
        │                                   ↑
        ├── feat/1-wifi-check ──(确认后合入 integration)
        ├── feat/2-waterfall   ──(确认后合入 integration)
        ├── feat/3-ble-risk    ──(确认后合入 integration)
        ├── feat/4-guard-58g   ──(确认后合入 integration)
        └── feat/5-capture     ──(确认后合入 integration)
```

**关键规则：**

- 五个功能分支**全部从 main 切出**（`git checkout main && git checkout -b feat/N-xxx`），互相独立、互不依赖——这是"分"。
- main 上只有阶段 0 的地基代码；**功能分支永不直接合回 main**，最终统一合入 `integration` 分支再验收——这是"合"。
- 每个分支做完 → STOP → 人测试 → 人说"确认完成" → 该分支冻结（`git tag featN-done`），才允许切下一个分支。
- 提交纪律：小步提交，一个提交只做一件事；提交信息格式 `feat(N): xxx` / `fix(N): xxx` / `test(N): xxx`；**每次提交前 `pytest` 必须全绿**，红了不许提交。
- 顺序**从简到难**：1 → 2 → 3 → 4 → 5，不许跳号。

## 三、统一架构与接口契约（合并零冲突的保证）

阶段 0 在 main 上定义好以下契约，五个功能分支**只实现自己的模块文件**，不碰任何共享文件（注册是自动扫描的，连配置文件都不用改）：

```
repo/
├── core/                  # 地基（功能分支只读）
│   ├── serial_link.py     # esp-sdr 串口协议：连接、发指令、收帧
│   ├── snapshot.py        # Snapshot 数据类 + 解析
│   ├── scheduler.py       # 时间片轮转引擎：按注册模块的权重分配
│   ├── store.py           # SQLite + CSV 双写
│   ├── classifier.py      # 启发式分类器（带宽/时长/占空比）——仅 T5 需要调用，阶段0只留接口
│   └── registry.py        # 自动扫描 modes/ 下所有 ModePlugin 子类并注册
├── modes/                 # 五个功能各占一个文件，自动被发现
│   ├── __init__.py
│   ├── wifi_check.py      # T1
│   ├── waterfall.py       # T2
│   ├── ble_risk.py        # T3
│   ├── guard_58g.py       # T4
│   └── capture.py         # T5
├── output/                # 各功能自带输出函数（表格/PNG/HTML/告警）
├── tests/                 # 必含 mock 快照源，无硬件可全量自测
├── docs/                  # 阶段说明 + 验收记录
└── todo.md                # 单一事实源
```

**ModePlugin 契约**（`core/registry.py` 定义，所有功能模块必须实现）：

```python
class ModePlugin:
    id: str                  # "wifi_check" 等唯一标识
    name: str                # 中文名，用于报告
    slice_weight: float      # 时间片权重（占调度总配比）
    def scan_requests(self) -> list[ScanRequest]:
        """本模块当前想要的扫描计划：[(频点Hz, 带宽Hz, 驻留ms), ...]"""
    def on_snapshot(self, snap: Snapshot) -> None:
        """收到快照时的增量处理（统计/检测/存储）"""
    def produce(self) -> Output:
        """产出：表格/图/告警/抓档，STOP 门禁时人类调用的就是它"""
```

**统一数据 schema**：`Snapshot(ts, center_hz, bw_hz, bins_db[512], meta)`，落 SQLite；所有报告、瀑布图、告警都从这份存档读，任何模块不得自造格式。

**调度器合并语义**：每个模块声明 `slice_weight`，调度器自动按权重轮转（参考配比 WiFi 40 / BLE 30 / 5.8G 20 / 抓拍 10，各模块在自己的文件里改自己的数字）。合并=五个文件同时躺在 `modes/` 里，天然无冲突。

## 四、任务切片（执行顺序，从简到难）

### 阶段 0：地基（main 分支）

1. `/coord-init` 初始化项目；git init；写 `.gitignore`（venv、*.db、captures/）
2. 建 `core/` 六个文件：串口链接（对 esp-sdr 的命令集封装）、Snapshot 解析、调度器骨架（能按注册模块轮转发指令收快照）、SQLite/CSV 双写、registry 自动扫描、ModePlugin 契约类
3. 建 `tests/mock_source.py`：生成带 WiFi 突发/BLE 脉冲/微波炉噪声/未知信号的**假快照数据流**——这是后面所有功能无硬件自测的基础，必须先做好
4. pytest 全绿；`python -m app.demo` 用 mock 源跑通"注册→调度→收快照→入库"全链路
5. tag `v0.1.0-foundation`，**STOP** 等人验收

### 任务 1：WiFi 信道体检（`feat/1-wifi-check`）——最简单，先建立信心

- `modes/wifi_check.py`：扫 2.4G ch1–13 + 5G ch36–165 主信道，按信道聚合占用率（N 轮扫描取均值）
- `output/`：信道占用表（按占用率排序）+ 选信道建议（避开占用最高的 3 个信道）
- 验收标准：mock 数据中人为塞高占用信道 → 表格排序和建议正确；真机结果与 ESP-WebSDR 网页肉眼对比基本一致
- **STOP：输出验收包（怎么跑、看到什么、预期数字），等人确认**

### 任务 2：周期性频谱瀑布图（`feat/2-waterfall`）

- `modes/waterfall.py`：周期性全频段轮扫（2.4G ISM / 5G 低段 / 5G 高段），快照顺路入库（不额外占用扫描时间）
- `output/`：从 SQLite 读历史，渲染时频热力图（PNG + HTML），横轴频率、纵轴时间，数小时跨度可翻页
- **注意输出物上必须标注"周期快照，非连续实时"**（单射频分时扫描的物理边界，不许美化）
- 验收标准：mock 源跑 10 分钟生成的瀑布图里，能肉眼分辨出塞进去的 WiFi 突发块和微波炉宽带噪声
- **STOP，等人确认**

### 任务 3：BLE 广播信道风险评估（`feat/3-ble-risk`）

- `modes/ble_risk.py`：驻留统计 2402 / 2426 / 2480 MHz 三个广播信道的占用量
- 风险评估逻辑（只评概率，不做设备级归因——这是边界，写进输出注释）：
  - 宽带占用高（WiFi 特征）→ 提示"WiFi 压制型风险，建议路由器挪信道"
  - 窄脉冲密集但 WiFi 空闲 → 提示"蓝牙设备密度型风险，建议减设备或降广播频率"
- 验收标准：两组 mock 场景（WiFi 压制型 / 蓝牙拥挤型）分别给出正确的风险类型判词
- **STOP，等人确认**

### 任务 4：5.8G 频段守卫（`feat/4-guard-58g`）

- `modes/guard_58g.py`：轮扫 5700–5900 MHz，检测持续性发射源（图传/模拟摄像头特征：窄带持续或规律跳频）
- 阈值告警 + 告警日志（出现时间、频点、带宽、持续时长）
- 验收标准：mock 中注入一个 5740 MHz 持续信号 → 告警触发且日志字段完整；无信号时段零误报
- **STOP，等人确认**

### 任务 5：可疑信号抓拍存证（`feat/5-capture`）——最难，压轴

- `modes/capture.py`：调用 `core/classifier.py` 实现启发式分类（带宽 / 持续时间 / 占空比三特征）；"未知"类别信号出现超阈值 → 触发原始 IQ 抓拍（多次 2ms 快照拼段，384KB SRAM 限制所致）
- 抓档带元数据存 `captures/`（时间、频点、IQ 文件、前后 30 秒频谱上下文）
- **酒店反偷拍模式**：一键扫描模式——对房间做全频段体检，输出"当前活跃发射源清单 + 可疑项已抓证据"，专门用于排查隐藏 WiFi 摄像头
- 验收标准：mock 注入未知调制信号 → 自动触发抓拍、文件落盘、清单报告生成；已知信号（WiFi/BLE）不触发
- **STOP，等人确认**

### 阶段 6：五合一合并（`integration` 分支）

1. 从 main 切 `integration` 分支
2. 按 1→2→3→4→5 顺序逐个 merge，**每合一个跑一次全量 pytest + mock 端到端**，红了当场修（只许改冲突行，不许改逻辑）
3. 全部合入后：验证调度器把五个模块的时间片配比正确轮转、互不阻塞
4. 输出总验收报告：五个功能各自的产出物 + 合并版全链路演示
5. tag `v1.0.0`，最终 STOP，等人做整体验收
