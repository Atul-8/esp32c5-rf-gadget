# 功能 1：WiFi 信道体检（feat/1-wifi-check）

> 本文件是阶段 1 的验收材料。所有数字都来自本机实跑（mock 与 COM56 实板各一遍），
> 没有"预期值"冒充实测值。

## 1. 做了什么

`modes/wifi_check.py`（单文件，未动 `core/`）：扫 2.4G ch1–13 + 5G ch36–165，
按信道聚合电平，输出「按相对抬升降序」的表格 + 推荐信道 + 建议避开前 3 + 干扰源列表。

## 2. 扫描计划（20MHz 窗 / 15MHz 步进重叠滑扫）

| 常量 | 值 | 依据 |
| --- | --- | --- |
| `SCAN_BW_HZ` | 20 MHz | 20 MS/s 实测整窗都是有效通带（80 MS/s 时约 60% 是 0 码） |
| `USABLE_HALF_HZ` | ±10 MHz | 同上 |
| `SCAN_STEP_HZ` | 15 MHz | 步进 < 窗宽 ⇒ 相邻窗重叠 5 MHz，频段不留空洞 |
| 2.4G 窗数 | 5（2412/2427/2442/2457/2472） | 覆盖 2402–2482 MHz |
| 5G 窗数 | 44（5180…5825，步进正好 15 MHz） | 覆盖 5170–5835 MHz |
| 每次驻留 | 100 ms / 1024 bin | 19.5 kHz 分辨率 |

**覆盖率掩码**：按信道 20 MHz 内「每个 MHz 格点是否真的收到能量（码 > 0）」求并集，
跨窗累加；`coverage < 60%` ⇒ 分档「无覆盖」，既不参与推荐也不计入干扰源。
这条是为了堵住「宽窗边缘 0 码 → 假空闲」的坑（旧口径实测 5G 外侧信道全读到 0%）。

## 3. 判决口径

```
信道中位电平 - 同频段最安静信道的中位电平 =
    0–8 dB   → 空闲
    8–15 dB  → 轻度
   15–25 dB  → 拥挤
    ≥25 dB   → 重度
```

**为什么是"相对抬升"而不是"高于噪声底的 bin 比例"**：实板同一帧内噪声底自身抖动
±10–18 dB（功率码 `20*log10(Q15)` 量化步长就有 6 dB），任何绝对门限都会把纯噪声判成
忙 —— 旧口径实测 2.4G/5G **全部信道 100% 忙**，推荐恒为「无干净信道」。改成同频段
相对抬升后，安静环境全归零、有 AP 的信道 +20…+40 dB，结果可解释、可复现。

**前提：固定增益**。硬件 AGC 会把每个信道都拉到相近电平（实测各信道 `p50` 落 62–77），
信道差异被吃掉。所以真机必须带 `--gain-index`（实测定稿 60：安静段 `p50≈28`、
忙段 `p50≈68`、无饱和）。

## 4. 验证命令（可复制）

```bash
cd examples/esp32c5-rf-monitor

# 1) 全量自测（58 条，含本功能 13 条）
python -m unittest discover -s tests -t .

# 2) 单功能 mock 自测（每条判据都能单独看）
python -m modes.wifi_check --scenario quiet      --slices 60
python -m modes.wifi_check --scenario wifi_busy  --slices 60
python -m modes.wifi_check --scenario microwave  --slices 60
python -m modes.wifi_check --scenario ble_crowded --slices 60

# 3) 真机（固定增益 60，60 秒）
python -m app.live --port COM56 --duration 60 --gain-index 60
```

## 5. mock 判据实测

| 场景 | 期望 | 实测 |
| --- | --- | --- |
| `quiet` | 全「空闲」、干扰源 0、推荐 ch1 | 干扰源 `无`，推荐 ch1 ✅ |
| `wifi_busy` | ch1/ch6 判忙、推荐落在干净的非重叠信道 | 避开 ch1/ch2/ch3，推荐 ch11 ✅ |
| `microwave` | 中段抬升、ch1 干净 | ch4–ch13 抬升，推荐 ch1 ✅ |
| `ble_crowded` | 不把 BLE 窄带脉冲算成 WiFi 负载 | 干扰源 `无`，推荐落在 1/6/11 ✅ |

## 6. 真机实测（COM56，`--gain-index 60`，60s / 17880 帧 / 错误 0）

| 排名 | 信道 | 比最静 | 分档 |
| --- | --- | --- | --- |
| 1 | ch36 (5.180 GHz) | +41 dB | 重度 |
| 2 | ch40 (5.200 GHz) | +40 dB | 重度 |
| 3 | ch44 (5.220 GHz) | +34 dB | 重度 |
| 4 | ch48 (5.240 GHz) | +28 dB | 重度 |
| 5 | ch153 (5.765 GHz) | +26 dB | 重度 |
| 6 | ch1 (2.412 GHz) | +22 dB | 拥挤 |
| 8–11 | ch8 / ch9 / ch2 | +19 dB | 拥挤 |
| 27 | ch100 (5.500 GHz) | +0 dB | 空闲 |

- 推荐：2.4G **ch11**（+3 dB）、5G **ch100**（+0 dB）
- 建议避开：2.4G ch1/ch8/ch9、5G ch36/ch40/ch44
- 覆盖列 38/38 全 100%，上一轮「5G 外侧假空闲」不再出现

## 7. 边界（不许美化）

- **分时快照，不是连续实时**：单射频按窗轮扫，一次 5G 全扫 ≈11 s，帧间有接收空档。
- **功率码是相对 dB 码，不是 dBm**：没有绝对校准，跨增益/跨天线不可比。
- 相对抬升只在「同一次固定增益扫描」内可比；换增益后历史数据不能直接比较。
- 判决是启发式：只回答「这个 20MHz 信道比本频段最安静的信道吵多少」，
  不做设备级归因、不区分 AP 与其它宽带源。
