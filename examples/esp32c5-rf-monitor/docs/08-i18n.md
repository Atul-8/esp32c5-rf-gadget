# 08 · 上位机英文界面零中文（i18n）

> 分支 `feat/7-fsm`｜硬约束：英文环境下，除「中文(CN)」切换按钮本身，屏幕上任何文字都不得是中文

## 问题：中文有两条来源

界面上出现的中文，一半来自网页写死的词条，另一半来自**模块现算出来的东西**：

| 来源 | 例子 | 前端能不能翻 |
| --- | --- | --- |
| 静态词条 | 表头「频点」「占空」、按钮「开始」 | 能（词典） |
| 模块产出 | 「判据④：宽带占用高还要看**时间上开不开**…」、体检结论、`render_text()` 的 ASCII 表 | **不能** |

第二类是带数字的成句判词，靠逐行翻译会打碎定宽对齐，数字一改模板就对不上。所以英文界面
走的是**两层分工**：静态词条归前端词典，模块产出在下行边界（Python → JS）就换掉。

```
modes/*.py  app/audit.py        ← 判据、门槛、判词（一个字不改，仍是中文原文）
        │
        │  web_payload() / tables() / audit()
        ▼
host/l10n.py  localize()        ← 中文串 → 英文模板（骨架匹配 + 数字回填）
        │
        │  to_json()  →  QWebChannel
        ▼
web/js/i18n.js  T()/apply()     ← 静态词条；en 缺 key 不回退中文，返回 key 并记账
        │
        ▼
        屏幕
```

## `host/l10n.py`：骨架 + 查表

三种写法，都遵循「翻不到就原样返回，绝不抛异常」：

```python
skeleton("带宽 12.5 MHz、占空 58%")   # → "带宽 {} MHz、占空 {}%"   数字段折叠成 {}
TABLE["带宽 {} MHz、占空 {}%"] = "bandwidth {} MHz, duty {}%"
translate("带宽 12.5 MHz、占空 58%")  # → "bandwidth 12.5 MHz, duty 58%"
```

- **只翻 `str` 的值，不翻 key**：前端按 key 取数，翻了就取不到。
- **占位数量必须与原文数字段一致**：`template.count("{}")` 不等于原文数字段数就原样返回——
  宁可留一句中文，也不给出错位的数字（错位比漏翻更难发现）。
- **数字段折叠的前提是句子骨架稳定**：所以「信道数量可变」这类句子必须按数量逐个列条目，
  不能用 `{}` 通配（`ch1, ch2` 里的 `ch1` 会被骨架化，模板就匹配不上）。

### 下行出口一览（新增出口必须同时补测试）

`tables()` · `describe()` · `stats()` · `sweep_state()` · `gain_state()` · `audit()` ·
`render_text()` —— 前六个都过 `_out(payload)`，最后一个见下。

### 两类句子骨架管不了

**① 列表长度会变**（`有明显抬升的信道：ch1, ch2, …`、`2.4G 避开：…`、`2.4G 在用：…`）。
骨架会把数字折叠成 `{}`，于是「6 个信道」和「7 个信道」是两个不同的键——按长度逐个备条目
迟早漏（真板就漏了 6 个这一档）。改走 `LIST_PATTERNS`：**正则换外壳，列表原样带回**，
长度任意都能翻。正则一律用**命名组**而不是 `\1` 反向引用：反斜杠跨工具传递极易被吃掉。

**② 异常文案**（`SerialLinkError: 连接已标记失效，请重新打开`）。它不走表格 payload，
里面常混着固件回显（`ERR fsm_args`）和字节数，骨架基本对不上。改走
`l10n.translate_error()`：先查表 → 再按 `ERROR_PHRASES` 片段替换 → 最后剔掉非 ASCII。
**保证零中文**是硬要求（英文界面宁可少信息也不能露中文），数字与设备回显尽量保留；
被剔掉的中文细节仍在终端日志里。界面侧统一走 `session.error_text(lang, exc)`。

## `render_text()`：英文模式不翻 ASCII，重新拼

`render_text()` 原本返回模块自己排的定宽 ASCII 表（中文表头 + 中文判词）。英文模式下**逐行
翻会打碎列对齐**，所以改成从已经本地化好的 `tables()` payload 重新拼一份纯文本：列宽由
数据算、表头由词典给，两个语言各自对齐。

## `web/js/i18n.js`：宁可亮 key，也不静默漏中文

```js
T("hdr.start")          // 按当前语言取词条，缺 key 时…… 
```

`en` 缺 key 时**不回退中文**，而是返回 key 本身并记进 `missing()`。理由：回退会让英文界面
悄悄冒出中文（正是本轮要禁的），而亮出 `hdr.start` 会被自检抓个正着。`missing()` 由自检汇总
成 `en_keys_complete` 这一项，缺一条就红。

配套三条规矩：

1. **语言切换时清空日志**：旧日志是切换前语言的，留着必然混语言（切完写一行提示）。
2. **`I18N.apply(host)` 必须在路由收尾时调**：浮层是切页时摘下来再挂回去的，太早了翻不到。
3. **浮层标题是面板标题的副本**，语言变了要再抄一次（`Popout.refreshTitle()`）；关浮层时
   必须**清空**标题，否则那份副本留在 hidden DOM 里变成幽灵文案。

## 英文下「逻辑会错」的坑：比中文量少但更阴

`level` / `risk_type` 这类字段在英文模式下**值已经变成英文**（`Heavy` / `Idle` /
`Suspicious` / `WiFi dominated` …）。前端原来拿中文字面量比较来决定标签颜色、3D 柱高、
推荐信道色调，英文下一律落到 `default` 分支——不报错、只是颜色和标签悄悄错了。

修法：`web/js/util.js` 的 `U.levelKey()` / `U.riskClass()` 把中英两套写法映射到同一个
语言无关的键（`heavy` / `crowded` / `light` / `idle` / `none` / `suspicious` / `review`），
所有「按档位决定样式」的判断一律走键，不再比字面量。

## 怎么验

| 层 | 命令 | 判据 |
| --- | --- | --- |
| 下行 payload | `cd host && python tests/test_l10n.py -v` | **22 tests**：10 场景 × 6 出口 + `render_text` 跑真实会话，另有列表句 1~12 长度 + 异常文案零中文；en 零 CJK，zh 仍有大量中文 |
| 网页 DOM（假固件） | `cd host && python app.py --selftest --seconds 10` | `en_no_cjk`（`hitCount == 0`）、`en_keys_complete`（`missingCount == 0`），自检 **52/52** |
| 网页 DOM（**真板 COM56**） | `cd host && python app.py --selftest --real --port COM56 --gain-index 60 --seconds 12` | **`EXIT=0`、`ok:true`、`hits 0`、`missing 0`、`checks 52` 全绿** |
| 骨架缺口 | `python testing/chk_l10n.py` | 运行时残留 `0 条` / `缺条目 0` / `占位不符 0` |
| 网页源码 | `python testing/_web_cjk.py` | 非兜底中文只剩双语言映射表与注释 |

自检的 DOM 扫描口径（`host/app.py` 的 `CJK_SCAN_JS`）：`TreeWalker` 扫 body 全部文本节点 +
`[title]` / `[placeholder]` / `option`，**豁免 `[data-lang-toggle]`**（只有语言切换按钮
允许出现「中文(CN)」）；6 个页面逐页 `Router.navigate` → 等 1.7 s（`raw` 页 2.6 s）→ 扫。

> 两个自检工程细节，踩过就写下来：**① 每次自检先重置 `localStorage["espsdr.lang"]` 回 zh**，
> 否则上一次跑留下的 en 状态会串进本次；**② 扫描会扫到 hidden 浮层**，浮层关掉时必须清标题。

## 边界

1. **只覆盖图形界面**：命令行（`app.live` / `app.demo` / `app.audit`）仍是中文，与本轮要求一致；
2. **判据一个字没改**：门槛、判词顺序、边界声明全在模块里原样保留，英文只是文案层；
3. **新增判词必须同时补 TABLE**，否则那条会原样漏中文（`tests/test_l10n.py` 拦这个）；
4. 英文模板是意译，不保证与中文逐字对应；数字段由原文回填，所以**数值本身不可能被翻译改掉**。
